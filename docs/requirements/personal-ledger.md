# 個人帳 — 需求與規格（v2.0.1）

個人帳第 1 批（個人交易）重新上線的規格。內容由 2026-10-15 開發與驗收過程中使用者逐項確認，對應分支 `feature/personal`。

- 對照版本：v2.0.1（`feature/personal`，基於 v1.5.2）
- 前身：v2.0.0（`c8578f1`）曾上線後撤回（`4b78361`）；本版 revert 該撤回後重新整合 v1.4～v1.5.2 的功能
- 不含：年繳訂閱拆月（G-6，v1.5.3／v1.6.0 的內容），之後另外合併

## 1. 背景與範圍

| 項目 | 結論 |
|---|---|
| 誰能用 | 每位成員都有自己的個人帳，包含一般成員（例：小妹） |
| 名稱 | 一律叫「個人帳」（設計稿寫「我的帳」，不採用） |
| 隱私 | 只有本人看得到；管理者也看不到別人的個人帳 |
| 裝置 | 家人各用自己的手機 |
| 本版範圍 | 個人交易的新增、查詢、修改、刪除，以及首頁、交易列表、統計、年度彙整依帳本切換 |
| 本版不做 | 個人分類、個人訂閱（固定支出）、個人預算——見第 6 節 |

## 2. 需求

### 2.1 帳本切換

| 編號 | 需求 |
|---|---|
| PL-01 | 側邊欄（手機在選單內）有「家庭帳／個人帳」切換；選中的一格白底、品牌色粗體，附圖示 |
| PL-02 | 帳本選擇**依帳號**記在裝置上，下次打開沿用；同一台裝置換人登入不沿用上一個人的選擇 |
| PL-03 | 切到個人帳時整套品牌色換成青綠（主色 `#0f8f7a`、深色 `#0b7565`、淺底 `#e3f4f0`、漸層 `#0f8f7a → #4fb389`、備註 `#5cb3a5`）；家庭帳維持紫色 |
| PL-04 | Logo 旁標題、載入畫面標題跟著帳本顯示「家庭帳／個人帳」 |
| PL-05 | 手機頂端顯示目前帳本的小標籤（兩本帳都顯示） |
| PL-06 | 個人帳隱藏「成員管理」；停在成員管理頁時切到個人帳，回到首頁 |

### 2.2 記帳

| 編號 | 需求 |
|---|---|
| PL-10 | 交易記在側邊欄目前的帳本；新增頁不另外提供帳本選擇 |
| PL-11 | 個人帳的記帳者固定是本人，不可代記他人（家庭帳照舊可代記） |
| PL-12 | 交易建立後不能在家庭帳與個人帳之間搬移 |
| PL-13 | 個人帳交易不能更換記帳者 |
| PL-14 | 個人帳可以記收入；家庭帳與個人帳的收入各自獨立，不共用 |
| PL-15 | 分類本版沿用家庭分類 |

### 2.3 各頁行為（個人帳模式）

| 頁面 | 行為 |
|---|---|
| 首頁儀表板 | 只算個人交易；分類卡片不顯示預算、不顯示「設定預算」；固定支出卡片保留（目前為 0） |
| 交易列表 | 只列自己的個人交易；不顯示成員篩選；記帳者欄保留（即本人） |
| 統計圖表 | 只算個人交易；比例條整段算在本人 |
| 年度彙整 | 只算個人交易；沒有年度額外開銷 |
| 預算／訂閱／分類設定 | 頂端提示「目前是個人帳，這裡顯示與修改的都是家庭帳」 |
| 成員管理 | 不顯示（PL-06） |

### 2.4 誰看得到

| 編號 | 規則 |
|---|---|
| PL-20 | 每位成員都有個人帳，與角色無關；一般成員也能記、能查自己的個人帳（2026-10-15 使用者更正：原 v2.0.0 限管理者） |
| PL-21 | 只有本人看得到自己的個人帳；別人的個人帳交易一律當作不存在（404），包含查詢、修改、刪除、修改紀錄；**管理者也不例外** |
| PL-22 | 改變角色（管理者 ↔ 一般成員）不影響看得到自己的個人帳 |

## 3. 資料庫

**本版沒有新增任何 migration。** 個人帳用的是 v1.3.0 就上線的 `sql/0002_owner_columns.sql`：

| 表 | 欄位／約束 | 意思 |
|---|---|---|
| `transactions` | `owner_id`（FK → `members`） | null＝家庭帳；有值＝該成員的個人帳 |
| `transactions` | `check (owner_id is null or owner_id = payer_id)` | 個人帳的擁有者必須是記帳者本人（PL-11 的資料庫保證） |
| `transactions` | 索引 `(owner_id, date)` | 依帳本查日期區間 |
| `main_categories` | `owner_id` | 第 2 批個人分類用；本版全為 null |
| `main_categories` | 系統分類唯一索引改為 `(owner_id, system_key)` | 每本帳各一組「其他／訂閱」 |

預算、訂閱、年度額外支出**沒有** `owner_id`，跟著分類決定屬於哪本帳（`api/src/services/scope.ts`）。所以第 2 批只要有個人分類，個人訂閱與個人預算不需再改資料庫。

API：交易、首頁、統計、年度彙整接受 `scope=family|personal`（預設 family，舊版前端不受影響）；新增交易可帶 `scope`；交易回傳多 `ownerId`。

## 4. SA 風險分析與使用者決定

| # | 風險 | 使用者決定 |
|---|---|---|
| O-01 | 記錯帳本後無法搬移，只能刪掉重記 | 接受；由使用者自行注意，換色已足夠辨識 |
| O-02 | 共用裝置會沿用上一個人的帳本 | 改為依帳號記住（PL-02） |
| O-03 | 收入記在個人帳會讓家庭結餘變少 | 不是問題：兩本帳的收入本來就各自獨立（PL-14） |
| O-04 | 分類共用，家庭停用分類會影響個人帳 | 分類要分家庭與個人，下一版做（PL2-01） |
| O-05 | 個人帳固定支出卡片永遠是 0 | 個人也有自己的訂閱，下一版做（PL2-02）；卡片先保留 |
| O-06 | 資料庫層沒有加密，能直接連資料庫的人看得到個人帳 | 記錄；隱私範圍是「App 內看不到」 |
| O-07 | 停用成員後，其個人帳資料留在資料庫、無人可見 | 尚未決定 |

## 5. 上線注意

1. **舊資料會重新出現**：v2.0.0 上線期間記過的個人帳會再出現。上線前可先查 `select count(*) from transactions where owner_id is not null;`
2. **版本號**：年繳分攤接回來時用 v2.1.0 以上，不要用 v1.6.0，否則版本會比 v2.0.1 小
3. **年繳分攤的 migration**：`0004_yearly_installments.sql` 隨 v1.6.0 加入後被撤回，本分支沒有。若正式庫曾在 v1.6.0 期間執行過它，資料庫會比程式多 `subscriptions.charge_month`、`period_amount` 兩欄；欄位可為 null，不影響本版運作，接回 G-6 時也是冪等可重跑
4. **若要再撤回**：撤回的是程式，`owner_id` 資料保留；下次帶回要先 revert 那次撤回

### 6.1 先記錄：使用者自己的個人帳分類（2026-10-15）

依使用者的個人試算表整理，第 2 批做個人分類時照這份建立。**這一版不建立**：v2.0.1 的個人帳沿用家庭分類，現在新增會出現在家庭帳的新增頁、分類設定與年度彙整。

| 個人分類 | 收支 | 性質 | 對應試算表的列 |
|---|---|---|---|
| 薪資 | 收入 | — | 薪資1、薪資2；獎金紅利（子分類「獎金」） |
| 其他 | 收入 | — | 被動收入、其它收入 |
| 食、衣、住、行、健康、育、樂 | 支出 | 浮動 | 同名 |
| 共同費 | 支出 | 固定（每月） | 共同費 |
| 交通費 | 支出 | 固定（每月） | 交通費 |
| 電話費 | 支出 | 固定（每月） | 電話費 |
| 孝親費 | 支出 | 固定 | 孝親費 |
| 投資 | 支出 | 固定（每月） | 股票 |
| 其他 | 支出 | — | 固定支出區的「其他」 |

注意：收入與支出都有「其他」，同名不同收支，程式與匯入都要用「名稱＋收支」辨識。

### 6.2 先記錄：匯入 2026 年 1～9 月個人試算表

個人分類做好後，比照家庭帳的 `api/src/db/force-import-2026.ts` 匯入。

| 項目 | 規則 |
|---|---|
| 記帳者 | 使用者本人（個人帳的 owner 必須等於記帳者，不能用「系統」成員） |
| 輸入者 `created_by` | null，備註加「（系統匯入）」 |
| 清除範圍 | 只清該使用者自己的個人帳 1～9 月，家庭帳與其他人的個人帳不動 |
| 金額 | 一律四捨五入成整數（例：9 月「樂」5,692.5 → 5,693；6、9 月電話費有隱藏小數） |
| 日期 | 每項每月一筆，該月最後一天；0 或空白略過 |
| 額外開銷欄 | 待第 2 批決定個人帳要不要有年度額外開銷後再處理 |

匯入前要向使用者取得：成員 id；確認 3 月「住」的 `#REF!` ＝ 1,137（由當月小計 15,624 反推）。

### 6.3 先記錄：獨秀指數

使用者之後想在個人帳加「獨秀指數」，公式由試算表反推並驗算（1 月：52,733 ÷ 23,764 ＝ 2.2；52,733 ÷ 43,764 ＝ 1.2）：

| 指數 | 公式 |
|---|---|
| 不含投資 | 月收入 ÷ 月支出（不含「投資」分類） |
| 含投資 | 月收入 ÷（月支出 ＋ 投資） |

所以「投資」必須是獨立分類，不能併入「其他」。待決定：App 的總支出與結餘要不要計入投資。試算表不計入，所以兩邊的結餘每月會差一筆投資金額。
